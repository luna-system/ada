## Integration Points

### Where New Meets Old

#### 1. **Tool Execution** (CRITICAL)
**Issue:** ReasoningLoopController simulates tool execution, but we have REAL tools in ada-chat!

**Current tools (ada-chat):**
- `ada_introspect`, `ada_search_memory`, `ada_read_file`, `ada_search`, `ada_list_files`, `ada_symbols`, `ada_git_status`

**Solution:** Bridge between reasoning loop and extension tools
```python
# In loop_controller.py
async def _execute_tool(self, request: ToolRequest) -> ToolCall:
    # Option A: Call ada-chat tools via API/IPC
    # Option B: Implement tools server-side in brain/
    # Option C: Hybrid (some client-side, some server-side)
```

**Recommendation:** **Option B for PoC** - Implement basic versions server-side
- Faster (no IPC overhead)
- Can parallelize easily
- Extension tools call brain for reasoning, brain doesn't call extension

#### 2. **Prompt Building** (NEEDS UNIFICATION)
**Issue:** Two prompt building paths now exist:

**Path 1 (Existing):** PromptAssembler.build_prompt()
- Uses ContextRetriever (parallel RAG)
- Activates specialists (parallel execution)
- Formats with SectionBuilder
- Optimized: <80ms

**Path 2 (New):** ReasoningLoopController._build_reasoning_prompt()
- Simple concatenation (PoC)
- Needs RAG context too!
- Should use same retrieval logic

**Solution:** ReasoningLoopController should USE PromptAssembler!
```python
class ReasoningLoopController:
    def __init__(self, ...):
        self.prompt_assembler = PromptAssembler()
    
    def _build_reasoning_prompt(self):
        # Use existing optimized system!
        base_context = self.prompt_assembler.retrieve_context(...)
        
        # Add reasoning-specific context
        reasoning_context = self._build_reasoning_context()
        
        return base_context + reasoning_context
```

**Benefits:**
- ✅ Reuse parallel RAG retrieval
- ✅ Reuse specialist activation
- ✅ No duplicate code
- ✅ All optimizations apply

#### 3. **Streaming Architecture** (COMPATIBLE)
**Good news:** Both systems use async generators!

**Existing:**
```python
async def stream_chat_async(prompt: str) -> AsyncGenerator:
    # Yields {"token": "text", "done": False}
```

**New:**
```python
async def reason() -> AsyncIterator[Dict[str, Any]]:
    # Yields {"type": "thought_chunk", "text": "..."}
    # Yields {"type": "tool_request", "tool": "..."}
    # Yields {"type": "convergence", "solution": "..."}
```

**Solution:** Nested streaming!
```python
async def reason():
    # Stream reasoning events
    yield {"type": "reasoning_step", "phase": "understanding"}
    
    # Stream LLM thoughts
    async for chunk in stream_chat_async(prompt):
        yield {"type": "thought_chunk", "text": chunk["token"]}
    
    # Stream tool execution
    yield {"type": "tool_request", "tool": "ada_search"}
    yield {"type": "tool_result", "result": "..."}
```

**Compatible!** Just different event types.

## Parallel Execution Opportunities

### Current Parallelization (v2.9.0)

**Already Optimized:**
1. ✅ RAG context retrieval (persona, memories, FAQs, turns) - 3.96x faster
2. ✅ Specialist execution (HIGH/CRITICAL priority) - 2.98x faster

### New Opportunities (v4.0)

**1. Multiple Tool Requests (HIGH IMPACT)**
```python
# LLM output:
"I need multiple things:
TOOL_REQUEST[ada_search:{"query":"auth"}]
TOOL_REQUEST[ada_list_files:{"path":"src/"}]
TOOL_REQUEST[ada_symbols:{"query":"validateToken"}]"

# Execute in parallel!
with ThreadPoolExecutor(max_workers=3) as executor:
    futures = [executor.submit(execute_tool, req) for req in requests]
    results = [f.result() for f in futures]
```

**Expected speedup:** 3x if all tools are independent!

**2. Importance Scoring (MEDIUM IMPACT)**
```python
# Score multiple tool results in parallel
with ThreadPoolExecutor(max_workers=4) as executor:
    scores = list(executor.map(
        calculate_importance,
        tool_results
    ))
```

**Expected speedup:** 2-3x for batch scoring

**3. SIF Encoding (FUTURE)**
When we add SIF compression:
```python
# Encode multiple files in parallel
with ThreadPoolExecutor() as executor:
    encoded = list(executor.map(
        sif_encode_file,
        files_to_compress
    ))
```

**Expected speedup:** 4-6x for large codebases

### Sequential Operations (MUST STAY)

**1. Reasoning Loop Iterations**
- CANNOT parallelize - each iteration depends on previous results
- LLM must think → execute tools → think again

**2. Convergence Detection**
- Must happen after each LLM output
- Sequential by nature

**3. Context Assembly (partially)**
- Base context can be parallel (already is!)
- Adding tool results must be sequential (order matters)

## Architecture Decisions

### Decision 1: Tool Execution Strategy

**Options:**
A. Extension tools only (client-side)
B. Brain tools only (server-side)
C. Hybrid (both)

**Recommendation: C - Hybrid**

**Brain-side tools (for reasoning loop):**
- `brain_read_file` - Read from workspace
- `brain_search_files` - Semantic search in RAG
- `brain_list_symbols` - Parse code structure
- `brain_analyze_deps` - Dependency graph

**Extension tools (for UI integration):**
- `ada_introspect` - Workspace analysis
- `ada_git_status` - Git operations
- `ada_run_terminal` - Execute commands
- `ada_edit_file` - File modifications

**Why:** Brain tools are fast (no IPC), extension tools access VS Code APIs

### Decision 2: Prompt Building Integration

**Option A:** Keep separate (duplicate code)
**Option B:** ReasoningLoopController uses PromptAssembler
**Option C:** PromptAssembler has "reasoning mode"

**Recommendation: B - Composition**

```python
class ReasoningLoopController:
    def __init__(self, ...):
        self.prompt_assembler = PromptAssembler()
    
    def _build_reasoning_prompt(self):
        # Get optimized base context
        base = self.prompt_assembler.build_prompt(
            user_message=self.state.user_request,
            conversation_id=self.conversation_id,
            include_specialists=True  # Only on first iteration
        )
        
        # Add reasoning-specific context
        reasoning_section = self._format_reasoning_state()
        
        return base + reasoning_section
```

**Benefits:**
- Reuses all optimizations (parallel RAG, specialists)
- No code duplication
- Consistent context across modes

### Decision 3: API Structure

**Option A:** New endpoint `/v1/chat/reason` (separate)
**Option B:** Mode parameter `/v1/chat/stream?mode=recursive`
**Option C:** Auto-detect (smart routing)

**Recommendation: A+C - New endpoint with auto-detection**

```python
# Explicit recursive reasoning
POST /v1/chat/reason
{
  "message": "Refactor auth to JWT",
  "max_iterations": 10
}

# Existing endpoint auto-detects complexity
POST /v1/chat/stream
{
  "message": "Refactor auth to JWT"  # Auto-routes to reason()
}
```

**Why:** New endpoint for explicit control, auto-detection for seamless UX

### Decision 4: State Persistence

**Question:** Should ReasoningState persist between requests?

**Recommendation: Yes, via conversation_id**

```python
# Store reasoning state in memory (or Redis for multi-instance)
reasoning_states: Dict[str, ReasoningState] = {}

# On request
state = reasoning_states.get(conversation_id) or ReasoningState(...)

# After reasoning
reasoning_states[conversation_id] = state
```

**Why:** Enables multi-turn reasoning, learning patterns

## Risk Analysis

### Technical Risks

**1. Complexity Explosion**
- **Risk:** Too many systems talking to each other
- **Mitigation:** Clear interfaces, good separation of concerns

**2. Performance Regression**
- **Risk:** Reasoning loop slower than expected
- **Mitigation:** Parallel execution, aggressive profiling

**3. Context Overflow**
- **Risk:** Reasoning accumulates too much context (>32k)
- **Mitigation:** SIF compression, adaptive thresholds

### Integration Risks

**1. Extension/Brain Coordination**
- **Risk:** Tools split between extension and brain causes confusion
- **Mitigation:** Clear tool ownership, hybrid strategy

**2. Streaming Complexity**
- **Risk:** Nested streaming causes UI issues
- **Mitigation:** Well-defined event types, thorough testing

**3. Backward Compatibility**
- **Risk:** New system breaks existing chat endpoint
- **Mitigation:** New endpoint, existing endpoint unchanged
