### Phase 2: Recursive Loop (Weeks 3-4) 🟢 CURRENT

**Goal:** Enable LLM-initiated multi-step reasoning with robust error handling

**🏗️ Architecture Decision: Workspace Access Strategy**

Different deployment scenarios require different workspace access approaches:

| Scenario | Access Pattern | Security | Implementation |
|----------|---------------|----------|----------------|
| **Dev (Docker)** | Brain has full workspace mount | Low risk (single user) | Current: `.:/workspace:ro` |
| **VS Code Extension** | Extension-side tools via API | Trusted (user's machine) | Phase 3: VS Code file API |
| **CLI** | Brain-side tools via filesystem | Low risk (local) | Brain direct access OK |
| **Web UI** | Sandboxed or deny file tools | HIGH RISK (multi-user) | Deny or sandbox per-user |
| **Matrix Bridge** | Per-user limits or no access | HIGH RISK (shared) | No file access or sandboxing |

**Solution:** Hybrid tool architecture (Phase 3)
- **Brain-side tools:** Memory search, RAG, internal state
- **Extension-side tools:** File operations via VS Code/IDE APIs  
- **Client-side tools:** User-specific sandboxed operations
- **Denied tools:** Multi-user scenarios get memory-only

## Technical Architecture

### Component Structure

```
brain/
├── reasoning/
│   ├── __init__.py
│   ├── state_tracker.py       # ReasoningState dataclass + tracking
│   ├── loop_controller.py     # Main reasoning loop orchestration
│   ├── sif_encoder.py         # Semantic compression (SIF format)
│   ├── importance_scorer.py   # Biomimetic importance calculation
│   ├── convergence.py         # Detect when LLM has solution
│   ├── tool_parser.py         # Parse TOOL_REQUEST[...] from output
│   └── context_manager.py     # Build context adapted to phase
├── schemas.py                 # Add ReasoningState, ToolRequest schemas
└── app.py                     # Add /v1/chat/reason endpoint
```

### API Design

**New endpoint:** `POST /v1/chat/reason`

```json
{
  "message": "Refactor auth to JWT",
  "mode": "recursive",  // or "oneshot" for backward compat
  "max_iterations": 10,
  "importance_threshold": 0.50,
  "stream_reasoning": true
}
```

**Response (SSE stream):**

```
event: reasoning_step
data: {"phase": "understanding", "thought": "I need to find auth files..."}

event: tool_request
data: {"tool": "ada_search", "params": {"query": "authentication"}}

event: tool_result
data: {"tool": "ada_search", "importance": 0.85, "detail": "FULL"}

event: convergence
data: {"solution": "...", "files_to_edit": [...]}
```

### Context Budget (32k tokens)

```
├── System prompt (2k)
├── Persona (1k)
├── Tool definitions (2k)
├── User request (0.5k)
├── Reasoning history (3k)
└── Dynamic context (23.5k) ← SIF-compressed tool results
```

**Key:** 23.5k is ENOUGH with semantic compression!

### SIF Encoding Example

**Before (1000 tokens):**
```typescript
// Full file contents (200 lines)
```

**After SIF (150 tokens):**
```yaml
file: utils/validation.ts
semantic_summary: "Email/password validation utilities"
exports: [validateEmail, validatePassword]
importance: 0.45
detail_level: SUMMARY
```

**Compression:** 6.7x smaller!

## Development Tips

### Fast Rebuilds
```bash
# Quick rebuild script (legacy builder, no cache, force recreate)
./scripts/dev-rebuild.sh brain

# Or manually:
DOCKER_BUILDKIT=0 docker compose build --no-cache brain
docker compose down brain
docker compose up -d brain
```

### Common Gotchas
- ❌ **Don't use:** `docker compose restart` - it doesn't pick up new images!
- ✅ **Do use:** `docker compose down` + `up` after rebuilding
- ⚡ **Speed tip:** We disabled buildx for dev - legacy builder is faster for iteration
- 📦 **Cache layers:** Docker has 4 separate caches (see DOCKER-CACHING-LESSONS.md)
